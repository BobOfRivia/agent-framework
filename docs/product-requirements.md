# 产品需求与初版范围

版本：v0.1；基线日期：2026-11-15。状态：已形成设计，尚未实现。需求依据为本仓库所有者的项目讨论，技术默认不是额外用户承诺。

## 1. 产品目标

提供可组合的Agent基座，由Creator装配不同场景的个人助手和数字员工。用户在项目群或个人入口发布任务，显式选择local/cloud；云端任务独立执行，个人电脑关机后继续。统筹员工协调多个已配置员工与获授权的个人助手，以可审阅文件和实际工作结果交付。

核心价值是可复用身份、能力、任务、执行与协作合同。LangGraph/Deep Agents负责执行基础，产品自己掌握员工归属、授权、Creator、任务权威状态、产物和审阅。

复用原则已确认：通用harness、官方checkpointer、Codex、沙箱adapter、浏览器/办公库、标准认证与观测优先使用成熟实现。各岗位主要是prompt+skills+tools配置；产品不发展成自研通用队列、浏览器或文件格式引擎。调度由M0比较成熟队列与外层Temporal后决定，见[复用策略](architecture/reuse-strategy.md)。

## 2. 已确认与可调整默认

已确认：数字人指角色、任务、工具与协作的数字员工；先本人/小团队使用再产品化；主框架LangGraph/Deep Agents；coding是按需使用的基础能力；Creator以参数/提示词/能力装配为主，也支持需要时生成代码、测试、发布。

已确认：“离线”指用户离线或电脑关机后云任务继续，不要求断互联网的本地模型。任务发起前选择云端，即直接委派云端Agent；不要求本地进行中任务自动迁移。

后续澄清：首版团队数字员工在云端；个人端承担依赖本机资源的工作。编码员工直接内置现成Codex，平台做集成、任务约束、测试与发布，不自建编程Agent内核。

默认：Python后端、Web内置IM式协作台、Python本地daemon/CLI、Linux云端/macOS本地、单可信团队私有Beta。原生桌面壳、其他OS与外部IM渠道按后续需求扩展。

## 3. 用户与场景

- 个人用户：创建个人助手，授权特定资料/目录/账号，选择本地或云端处理任务。
- 团队成员：在项目群安排工作，邀请专业员工或个人助手，审阅并继续修改产物。
- Creator使用者：用自然语言描述岗位或业务需求，检查配置、能力、权限需求和测试结果，再发布员工版本。
- 管理者：维护团队成员、可用能力、账号连接、预算和运行状态；不自动获得成员个人资料权限。
- 编码/领域专员：为Creator解决能力缺口，产出可复用工具、技能和验证证据。

## 4. 需求基线

MUST为M7验收前必需；阶段内可逐步实现。SHOULD为不改变关键合同的体验增强；LATER明确排除首版。

| ID | 级别 | 需求与完成边界 |
| --- | --- | --- |
| R-01 | MUST | 同一基座支持个人/团队归属；分离定义、不可变revision与长期实例；版本更新不影响进行中的任务 |
| R-02 | MUST | 能力目录可组合参数、prompt、skills、tools；验证依赖、环境、输入输出和权限要求；coding按需可用 |
| R-03 | MUST | Creator先装配已有能力，有缺口时委派内置Codex编码员工生成至少一种可复用Python工具扩展，测试后发布；不自研编码Agent |
| R-04 | MUST | 创建Task时显式选择local/cloud；目标固定，能力不兼容时拒绝；换位置新建明确任务 |
| R-05 | MUST | 云worker独立于客户端存活；员工身份持续存在；支持任务/事件唤醒与基础持久定时触发 |
| R-06 | MUST | 本地daemon可配对、授权目录、接收任务、报告状态、撤销与重连；离线等待且不静默上传 |
| R-07 | MUST | Web项目群/私聊/任务线程；可邀请人和Agent实例、@路由、查看任务和文件；不要求完整通用IM产品 |
| R-08 | MUST | 云统筹员工经任务工具拆解、委派、等待和汇总；每Task一个负责人；同部署个人/团队通过预授权pair协作 |
| R-09 | MUST | 区分Conversation、Task、ExecutionSession与RunAttempt；持久恢复、租约排他、暂停/取消/返工/终态retry |
| R-10 | MUST | 持久TaskWorkspace和版本化Artifact；带来源/hash/ACL；计算回收不丢正式交付物 |
| R-11 | MUST | 个人/团队Space隔离；有效授权交集；工具审批绑定具体动作；私聊/记忆/账户不因入群自动分享 |
| R-12 | MUST | 任务/调用/用量可追踪，预算限制含子任务及重试；事件可补拉；日志脱敏 |
| R-13 | MUST | 配置和扩展具有样例测试、验证报告、不可变发布、回滚默认版本；失败版本不可调度 |
| R-14 | MUST | 结果送审、接受/返工、按产物版本验收；区分成果review与工具approval；不以自然语言自称完成作唯一依据 |

SHOULD：角色模板、任务复制、清晰的阻塞原因与恢复入口、字段差异预览、可筛选事件、成本估算提示。它们优先服务MUST闭环，不先做大规模模板市场或复杂视觉编排器。

## 5. 首版明确范围

- 一个可信团队与同一部署内个人空间；有基本多用户身份与授权，不能用全局共享账号代替。
- 同一Deep Agents运行adapter覆盖local/cloud；工具及环境差异通过注册能力/配置解决。
- 编码任务使用Codex专用adapter，仍遵守统一Task/Space/Artifact合同；通用任务保留Deep Agents。团队员工默认cloud，依赖本机能力时委派个人助手。
- 一个完整云端办公场景、一个本地数据场景、一个Creator编码扩展场景，详见[验收](acceptance.md)。
- Creator自动生成的代码扩展仅支持受限Python工具包；新的runtime、控制面插件、权限策略实现需可信工程开发。
- Web协作台为首个IM入口；本地daemon/CLI提供电脑能力；不以“只有CLI”替代群协作，不以“只有Web上传”替代本机执行。
- 开发Docker验证沙箱生命周期和受限执行；真实云验收在与个人电脑不同的主机上进行。

## 6. 后置范围

原生桌面完整客户端；任意第三方Agent联邦/市场；云本地自动迁移和进程热迁移；全盘/浏览器cookie自动同步；每员工永久VM；复杂共享实时编辑；自主修改生产权限；公开敌对多租户SaaS安全承诺；语音形象/视频虚拟人。

## 7. 产品规则

个人助手是长期个人身份，云执行不改变归属；员工常驻表示可被寻址、唤醒和恢复，不表示持续消耗模型或独占VM。Creator发布定义与实例授权分别进行。

一项任务的目标、执行位置、负责人、版本、预算和验收合同发布时确定。统筹分工必须产生真实任务记录，成员自己的上下文不默认共享。个人助手提供数据需目标owner预授权，仅回传允许共享的结果。

数据、暂停恢复、工具拒绝、预算和终态细则统一在[领域合同](domain-model.md)，不在每个prompt中各自定义。界面状态必须对应服务端事实。

## 8. 初版成功标准

[14个工作包](development-plan.md)按依赖交付；[27条验收](acceptance.md)全部具备证据；三类真实模型业务场景各5次至少4次达到rubric；权限、审批、旧fence和未知副作用负例全部通过。单团队负载/响应目标按验收环境测量，不推导公开SaaS SLA。

## 9. 变更规则

用户后续修订优先。新增需求需标级别、工作包和AC映射；涉及状态、隔离、版本或执行位置的变化先更新ADR和主合同。技术选型与产品承诺的未决项见[风险清单](risks-and-open-questions.md)。
