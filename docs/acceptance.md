# 初版验收标准

状态：v0.1，2026-11-15；**以下全部为待实现验收目标，不是现有通过报告**。需求号见 [PRD](product-requirements.md)，映射见 [追踪表](traceability.md)。

## 1. 验收环境与证据

至少准备：独立 Linux 云主机（API/worker/数据库/沙箱可同主机分进程）、一个 macOS 本地执行器、个人 Space A、团队 Space T、无权用户 B、统筹/研究/分析/个人助手四实例、已登记模型provider、真实文件样本、外部写工具测试服务。

每条证据记录：AC号、git SHA、依赖锁、环境、测试命令、Task/Run/Event/Artifact ID、预期与实际、通过/失败/未验证。日志与样本必须脱敏。安全负例、租约防重放、审批绑定与数据隔离要求全部通过；不能用总体成功率抵消。

## 2. 功能与系统验收

| 编号 | 操作／条件 | 必须观察到的结果 |
| --- | --- | --- |
| AC-01 声明合同 | 验证4个Agent样例；提交未知字段、未知能力、缺依赖及错误参数 | 有效定义被接受；无效输入在实例化/执行前明确拒绝；draft修改使验证失效 |
| AC-02 身份与空间 | 同定义创建个人/团队实例，分别写记忆；用户B尝试读取 | 配置可复用；实例记忆与凭据独立；越权查询拒绝且不泄露元数据 |
| AC-03 位置固定 | 分别创建local/cloud任务；设备失联；伪造PATCH改位置 | 任务实际按声明位置执行；无自动迁移；修改拒绝，显式新任务可用 |
| AC-04 云后台运行 | 远端任务开始后关闭桌面客户端／断开本机网络至少10分钟，任务期间需有执行步骤 | 云端继续完成并保留事件/文件；重新登录可见结果；不是预先完成或本机假cloud |
| AC-05 本地离线 | 设备离线时提交local；运行中断网；重新连接 | 未开始任务blocked/waiting_device，重连后仅一次有效attempt；已开始未知动作进入核对 |
| AC-06 统筹委派 | 群内发起研究任务，要求研究/分析并行再汇总；一个分支失败 | 真实子Task和负责人存在；依赖与预算受控；失败不被伪报成功；审阅前有产物 |
| AC-07 个人团队协作 | Team统筹请求个人助手资料；测试未授权、授权、撤销三种情况 | 未授权拒绝；授权只返回允许结果；源方不能读目标私有session/记忆；撤销阻止后续访问 |
| AC-08 状态操作 | queued/running下pause，blocked下resume，review返工，cancel和retry | 符合规范状态机；安全边界暂停；终态不复活；retry创建新ID并保留来源 |
| AC-09 租约与fence | 两worker竞争、旧worker超时后晚回结果、并发取消 | 每Task仅一个有效执行权；旧fence不能派发新动作或发布产物；状态无倒退 |
| AC-10 持久恢复 | 在模型后、工具前、工具后、checkpoint前后分别杀worker并重启 | 从可确认检查点继续，保留session/workspace；无法确认的外部动作明确阻塞，无静默丢失 |
| AC-11 副作用 | 重投相同工具动作；模拟请求发出后回执丢失 | 有provider幂等支持则核对同receipt；不支持且结果不明则recovery_required，不盲目重试 |
| AC-12 工具审批 | 外发工具触发审批；批准后修改参数/版本；重复批准、过期审批 | 只有绑定动作可执行一次；变化、过期和非授权操作者被拒绝；等待不占有效运行租约 |
| AC-13 产物 | 生成真实表格/报告；两个分支并发提交；撤销共享后下载 | 文件可打开、hash/版本正确、来源可追踪；并发不互相覆盖；下载按当前ACL控制 |
| AC-14 配置Creator | 自然语言创建“竞品研究员”，仅使用已登记能力，测试后实例化 | 产生有效Spec、验证报告、不可变revision；新员工可实际完成样例，无需手改服务代码 |
| AC-15 编码扩展 | 给Creator现有目录没有的“特定CSV评分工具”需求，实际调用内置Codex SDK/CLI | 保存原生session与diff；生成Python包/schema/权限/测试；平台独立校验，发布后第二个新实例复用成功；不得用自研循环替代 |
| AC-16 发布与回滚 | 测试失败发布、两个编辑者覆盖、v1运行中发布v2并回滚默认 | 失败不发布；CAS冲突可见；旧Task仍绑定v1；新Task选当时默认；回滚不改历史 |
| AC-17 预算 | 递归委派、模型连续调用、并行子任务共同接近上限 | 总预算预留和结算可追踪；超限不再派发新调用；任务明确失败/阻塞策略；取消后有账单尾差记录 |
| AC-18 事件补拉 | SSE断开、重复投递、按Last-Event-ID重连、过期cursor | 持久事件顺序一致、客户端去重、状态可重建；过期有明确快照恢复路径 |
| AC-19 执行隔离 | sandbox代码读未挂载路径、访问元数据网、取得主凭据；创建恶意扩展 | 预定负例全部拒绝；工具不绕过网关；记录Docker边界；不能据此宣称公开多租户安全 |
| AC-20 群协作 | 邀请/移除Agent，@负责人，私聊给敏感信息，群中索要私聊内容 | 仅授权成员可见；不唤醒全群；移除后停止新任务路由；私聊不自动泄漏到群 |
| AC-21 可观测性 | 注入模型/工具/设备错误和敏感测试凭据，按Task追踪 | Task/Run/tool/artifact可关联；凭据脱敏；看到等待/失败原因和用量而非只有“错误” |
| AC-22 部署恢复 | 新环境按文档部署；恢复数据库和artifact备份；清理过期环境 | 可复现；恢复后引用与hash一致；资源无孤儿或可发现重试；明确RPO/RTO测量值 |
| AC-23 真实质量 | 三个标准场景各重复5次，保持模型/输入/预算记录一致 | 每场景至少4/5达到结果rubric；权限与副作用负例100%通过；不能只评估聊天回答 |
| AC-24 同一基座 | 相同AgentRevision分别在已允许的local/cloud任务中处理等价样本 | 共用核心运行adapter与合同；位置、目录、事件、产物记录准确，不通过复制两套逻辑伪装统一 |
| AC-25 能力兼容 | 本地专用能力选cloud、缺Python依赖、无网络策略能力、未授权连接 | 发布/派发前报告具体不兼容；执行时仍检查；不默默扩大工具和网络权限 |
| AC-26 常驻与日程 | 员工空闲后回收计算；定时触发；调度器重启/重复tick | 身份与记忆仍在；按需唤醒；同(schedule_id,scheduled_at)只创建一个Task；无LLM空转轮询 |
| AC-27 组件复用与调度选型 | 检查M0决策、锁定依赖、选定adapter及故障实验 | 现成队列/外层Temporal有比较与明确选择；重试/恢复单一权威；框架原生能力不重复实现；每类先一个provider；变更控制面所需合同已同步，不能靠候选清单判定完成 |

编码profile补充：AC-08/10/12分别验证Codex原生暂停、恢复与审批，不用LangGraph checkpoint代替；未支持能力应明确拒绝或recovery_required，不重复启动job。AC-17按可验证job时间/资源和原生可用统计验收，不支持的调用上限请求必须422。AC-19分别验证Deep Agents逐工具网关与Codex job隔离/原生权限，不能声称拦截全部Codex内部工具。AC-03/24验证团队员工cloud策略和个人助手显式local选择。

## 3. 三个正式业务场景

### S1：群内竞品研究与分析

创建统筹、研究员、分析员；群内任务选择云端；个人助手经授权提供背景摘要；研究与分析并行；生成带来源引用的Markdown报告和CSV/XLSX数据；统筹核验并送审。

Rubric：任务要求全部覆盖；关键事实能定位到来源且实际支持结论；表格与报告数据一致；不虚构委派或产物；共享范围符合授权；失败分支清楚报告。验收样本保存固定网页快照/公开文档以支持回归，另做一次实时检索验证。

### S2：本地表格处理

个人助手本地读取已授权根目录中的CSV，按规格计算并生成结果；未授权目录访问被拒绝。复制同等已批准输入到云端后，另建cloud任务，由同revision完成等价分析。原本地Task不迁移、不共享原始绝对路径。

Rubric：数值与确定性参考计算一致；输入未被意外覆盖；输出可打开；根目录与产物授权正确；断连不会重复执行已完成写入。

### S3：Creator缺口扩展

需求：创建供应商评分员工，现有能力无法完成特定CSV字段规则。Creator调用编码专员生成工具，运行正常/缺字段/非法数值/越权路径测试，发布工具和员工版本；全新实例完成样例；修改工具后产生新版本，旧任务仍可追踪旧包。

编码专员使用现成Codex，须有SDK/CLI版本、真实调用、文件diff与独立测试证据。原生中断/取消/恢复需单独验证，不能用LangGraph checkpoint测试替代。

Rubric：真正安装/加载受限扩展并执行；计算值正确；错误输入明确失败；构建和运行不读取平台主凭据；记录依赖、包digest、权限和测试证据；失败版本不能成为current。

## 4. 非功能目标与发布 gate

- 单团队验收基线：3个人类用户、4个Agent实例、10个排队任务、最多4个并行Run；硬件与模型分别记录。
- 排除模型与沙箱启动时间后，任务创建 API p95 <= 1s；空闲云worker可领任务时，入队到领取 p95 <= 5s；持久事件到在线UI p95 <= 2s。每项至少100次，报告样本和环境。
- 设备离线识别默认45s内（15s心跳，允许调度误差另记）；恢复时间、冷启动、模型延迟测量并公开，不在未测前承诺。
- 每阶段安全负例零失败，关键合同不变量零违反，全部必选AC有证据；未满足则不能标记M7完成。
- 面向真实用户前完成一次恢复演练与凭据撤销演练。公开敌对多租户、合规认证、跨平台本机应用全面支持均不由本Beta验收推导。
